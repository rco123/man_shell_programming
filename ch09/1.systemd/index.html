  • 9. 스크립트
  • 9.1 systemd I

systemctl (root)

1. 개요

Jetson 환경에서 myapp이라는 사용자 지정 애플리케이션을 **시스템 서비스(systemd 서비스)**로 실행하는 방법을 설명합니다.
이 과정에서 **서비스 유닛 파일(myapp.service)을 작성하고, 실행 및 관리하는 방법**을 다룹니다.

2. myapp.sh 실행 파일 생성

먼저, 실행할 **스크립트 파일(myapp.sh)을 작성**합니다.

1) 실행할 스크립트 생성

sudo vi /usr/local/bin/myapp.sh
다음 내용을 입력합니다. 
#!/bin/bash
while true; do
    echo "$(date) - myapp is running" >> /var/log/myapp.log
    sleep 10
done

  • #!/bin/bash → Bash 스크립트로 실행됨을 명시
  • while true; do ... done → 무한 반복 실행
  • echo "$(date) - myapp is running" >> /var/log/myapp.log
    • 현재 날짜와 함께 myapp 실행 로그를 /var/log/myapp.log 파일에 저장
  • sleep 10 → 10초마다 실행됨

2) 실행 권한 부여

sudo chmod +x /usr/local/bin/myapp.sh

3. 서비스 유닛 파일(myapp.service) 생성

이제 **myapp.sh를 systemd 서비스로 등록**하는 myapp.service 파일을 생성합니다.

1) 서비스 유닛 파일 생성

sudo vi /etc/systemd/system/myapp.service
아래 내용을 입력합니다.

[Unit]
Description=My Application Service
After=network.target

[Service]
ExecStart=/usr/local/bin/myapp.sh
Restart=always
User=root
Group=root
StandardOutput=append:/var/log/myapp.log
StandardError=append:/var/log/myapp.log

[Install]
WantedBy=multi-user.target

4. myapp.service 옵션 설명

[Unit] 섹션

  • Description=My Application Service
  • 서비스에 대한 설명을 제공
  • After=network.target
  • 네트워크가 활성화된 후에 실행됨
  • 네트워크 연결이 필요한 서비스라면 반드시 추가

[Service] 섹션

  • ExecStart=/usr/local/bin/myapp.sh
  • /usr/local/bin/myapp.sh 스크립트를 실행
  • Restart=always
  • 서비스가 중단될 경우 자동 재시작
  • 가능한 옵션:
    • no → 자동 재시작 안 함
    • always → 항상 다시 시작 (예기치 않게 중단되어도 재시작)
    • on-failure → 오류 발생 시 재시작 (정상 종료 제외)
    • on-abnormal → 비정상 종료 시 재시작
  • User=root
  • 서비스를 실행할 사용자 지정 (root)
  • Group=root
  • 서비스가 속할 그룹을 지정
  • StandardOutput=append:/var/log/myapp.log
  • 서비스의 표준 출력을 /var/log/myapp.log에 저장
  • StandardError=append:/var/log/myapp.log
  • 서비스의 표준 에러를 /var/log/myapp.log에 저장

[Install] 섹션

  • WantedBy=multi-user.target
  • 부팅 시 자동 실행할 대상 설정 (multi-user.target은 텍스트 기반 실행 환경)

5. 서비스 등록 및 실행

1) systemd에 서비스 등록

sudo systemctl daemon-reload
- 새로 추가한 myapp.service 파일을 systemd가 인식하도록 설정

2) 서비스 실행

sudo systemctl start myapp
- myapp.sh 스크립트가 실행됨

3) 서비스 상태 확인

systemctl status myapp
출력 예시: 
● myapp.service - My Application Service
   Loaded: loaded (/etc/systemd/system/myapp.service; enabled)
   Active: active (running) since Mon 2024-02-26 10:00:00 UTC; 2min ago
 Main PID: 1234 (myapp.sh)
   CGroup: /system.slice/myapp.service
           └─1234 /bin/bash /usr/local/bin/myapp.sh
- Active: active (running) → 정상 실행 중 - Main PID: 1234 (myapp.sh) → 실행된 프로세스의 ID 확인 가능

6. 서비스 자동 실행 설정

부팅 시 자동 실행을 설정하려면 enable 명령어를 사용합니다.

sudo systemctl enable myapp
이제 시스템이 재부팅될 때 myapp 서비스가 자동으로 실행됩니다.

자동 실행을 해제하려면 다음 명령어를 사용합니다. 

sudo systemctl disable myapp

7. 서비스 중지 및 재시작

  • 서비스 중지 
    sudo systemctl stop myapp
  • 서비스 재시작 
    sudo systemctl restart myapp

8. 서비스 로그 확인

서비스 실행 중 생성된 로그를 확인하려면 journalctl을 사용합니다. 

journalctl -u myapp --no-pager

특정 날짜 이후의 로그만 확인하려면: 

journalctl -u myapp --since "2024-02-26 10:00:00"

9. 전체 명령어 정리

명령어 설명
sudo systemctl daemon-reload 서비스 설정 변경 적용
sudo systemctl start myapp 서비스 실행
sudo systemctl stop myapp 서비스 중지
sudo systemctl restart myapp 서비스 재시작
sudo systemctl enable myapp 서비스 부팅 시 자동 실행 설정
sudo systemctl disable myapp 부팅 시 자동 실행 해제
systemctl status myapp 서비스 상태 확인
journalctl -u myapp 서비스 실행 로그 확인

10. 정리

  • myapp.sh 스크립트를 작성하여 **무한 루프 실행 및 로그 저장 기능**을 추가
  • myapp.service 유닛 파일을 생성하고 systemd를 통해 서비스로 등록
  • ExecStart에서 /usr/local/bin/myapp.sh를 실행하도록 설정
  • Restart=always를 설정하여 비정상 종료 시 자동 재시작
  • User=root, Group=root을 설정하여 root 사용자 권한으로 실행
  • StandardOutput, StandardError를 설정하여 로그 파일에 출력 저장
  • systemctl 명령을 사용하여 서비스 시작, 중지, 자동 실행 설정 가능

이제 myapp.sh가 **Jetson에서 systemd를 통해 자동 실행되는 서비스**로 동작합니다.

systemd 서비스에서 실행된 프로그램과 로그인 셸(.bashrc) 환경변수 차이점

systemd 서비스에서 실행된 프로그램과 로그인 셸(.bashrc) 환경변수 차이점

1. systemd 서비스에서 실행된 프로그램의 환경변수

  • systemd는 독립적인 환경**에서 실행되므로, **로그인 셸에서 설정된 환경변수를 자동으로 로드하지 않습니다.
  • 즉, sudo systemctl start myapp으로 실행된 프로그램은 **.bashrc나 .profile에서 설정된 환경변수**를 자동으로 상속받지 않습니다.
  • 대신, systemd는 /etc/environment 및 서비스 유닛 파일(myapp.service)에서 정의된 환경변수만 사용합니다.

2. 로그인 셸에서 실행될 때와의 차이점

실행 방식 .bashrc 적용 여부 환경변수 로딩
터미널에서 직접 실행 (bash myapp.sh) 적용됨 로그인 사용자 환경변수 유지
systemctl start myapp 로 실행 적용되지 않음 /etc/environment 및 myapp.service 내 환경만 적용
  • 터미널에서 bash myapp.sh를 실행하면 **사용자의 로그인 환경변수(.bashrc, .profile)를 상속**합니다.
  • systemctl start myapp으로 실행하면 **로그인 환경변수 없이 실행**되므로, PATH, PYTHONPATH, LD_LIBRARY_PATH 등이 다를 수 있습니다.

3. systemd 서비스에서 .bashrc 환경변수 적용 방법

방법 1: Environment 옵션을 이용하여 환경변수 지정

서비스 유닛 파일(myapp.service)에 환경변수를 직접 추가할 수 있습니다.

[Service]
Environment="PATH=/usr/local/bin:/usr/bin:/bin"
Environment="PYTHONPATH=/home/jetson/.local/lib/python3.8/site-packages"
ExecStart=/usr/local/bin/myapp.sh
환경변수를 직접 지정하면 .bashrc를 로드하지 않아도 필요한 환경을 설정할 수 있습니다.

방법 2: ~/.bashrc 직접 로드

스크립트(myapp.sh) 내에서 .bashrc를 로드하도록 수정할 수도 있습니다.

#!/bin/bash
source /home/jetson/.bashrc
echo "환경 변수 적용됨: $PATH"
while true; do
    echo "$(date) - myapp is running" >> /var/log/myapp.log
    sleep 10
done
이렇게 하면 systemd 서비스에서도 .bashrc에서 설정한 환경변수를 사용할 수 있습니다.

방법 3: systemd의 User= 옵션 활용

  • User=jetson을 설정하면, myapp 서비스는 jetson 사용자의 환경에서 실행되지만, 여전히 .bashrc는 자동으로 로드되지 않습니다.
  • shell이 실행되지 않기 때문입니다.

이 경우, ExecStart에서 /bin/bash -lc 옵션을 추가하면 **로그인 셸 환경을 강제로 적용**할 수 있습니다.

[Service]
ExecStart=/bin/bash -lc "/usr/local/bin/myapp.sh"
이 설정을 사용하면 로그인 환경(.bashrc, .profile)이 적용된 상태에서 실행됩니다.

4. 정리

  • systemd에서 실행되는 서비스는 기본적으로 .bashrc를 로드하지 않음.
  • 터미널에서 실행하는 경우와 환경변수가 다를 수 있음.
  • .bashrc를 적용하려면:
  • Environment 옵션으로 필요한 환경변수를 직접 설정
  • myapp.sh에서 source ~/.bashrc를 추가
  • ExecStart를 /bin/bash -lc로 변경하여 로그인 셸 환경에서 실행

이제 systemd 서비스에서 로그인 셸과 동일한 환경을 적용하는 방법을 이해할 수 있습니다.
