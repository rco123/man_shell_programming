쉘에서 명령 실행

쉘에서 **명령이 끝난 후 다음 명령으로 전달하는 방법**에는 여러 가지가 있음.
각 방법은 실행 순서, 성공/실패 여부, 데이터 전달 방식에 따라 다르게 동작함.

1. ; (세미콜론) - 순차 실행

  • 각 명령을 순서대로 실행 (앞 명령어가 성공하든 실패하든 다음 명령 실행)
  • 독립적인 명령어 실행 
echo "첫 번째 명령어 실행"; echo "두 번째 명령어 실행"

실행 결과

첫 번째 명령어 실행
두 번째 명령어 실행
✔ 핵심 정리
  • 첫 번째 명령어 실행 후 무조건 두 번째 명령어 실행
  • 성공/실패 여부와 관계없이 다음 명령 실행

2. && (AND 연산자) - 앞 명령이 성공하면 실행

  • 첫 번째 명령이 성공(0)하면 두 번째 명령 실행
  • 첫 번째 명령이 실패(0이 아닌 값 반환)하면 두 번째 명령 실행 안 함 
mkdir test_dir && cd test_dir

실행 결과 (성공 시)

(디렉토리 생성 후 `cd test_dir` 실행)

실행 결과 (실패 시)

mkdir: cannot create directory ‘test_dir’: File exists
(디렉토리가 이미 존재하면 `cd test_dir` 실행 안 함)
✔ 핵심 정리
  • 첫 번째 명령이 성공(0 반환)해야 두 번째 명령 실행
  • 연속적인 작업을 할 때 유용 (예: 디렉토리 생성 후 이동)

3. || (OR 연산자) - 앞 명령이 실패하면 실행

  • 첫 번째 명령이 실패(0이 아닌 값 반환)하면 두 번째 명령 실행
  • 첫 번째 명령이 성공하면 두 번째 명령 실행 안 함 
mkdir test_dir || echo "디렉토리 생성 실패"

실행 결과 (성공 시)

(디렉토리가 생성되었으므로 `echo` 실행 안 함)

실행 결과 (실패 시)

mkdir: cannot create directory ‘test_dir’: File exists
디렉토리 생성 실패
✔ 핵심 정리
  • 첫 번째 명령이 실패(0이 아닌 값 반환)하면 두 번째 명령 실행
  • 예: 오류 메시지를 출력할 때 사용

4. | (파이프) - 앞 명령의 출력을 다음 명령의 입력으로 전달

  • 첫 번째 명령어의 출력을 두 번째 명령어의 입력으로 사용
  • 데이터 흐름을 연결하여 활용 가능 
ls -l | grep ".sh"

실행 결과

-rwxr-xr-x  1 user user  4096 Feb 26 10:00 script.sh
(현재 디렉토리에서 .sh 파일만 출력)

✔ 핵심 정리
  • 데이터를 연속적으로 처리할 때 사용
  • 출력을 필터링하거나 가공할 때 유용

5. & (백그라운드 실행) - 명령을 백그라운드에서 실행

  • 명령을 백그라운드에서 실행하고 즉시 프롬프트로 돌아옴 
sleep 10 &

실행 결과

[1] 12345  (프로세스 ID 출력)
(백그라운드에서 실행되며, 즉시 다음 명령어 입력 가능)
✔ 핵심 정리
  • 백그라운드에서 실행하고 다음 작업을 즉시 수행 가능
  • 백그라운드 프로세스의 PID 확인 가능

6. () (서브셸 실행) - 별도의 프로세스로 실행

  • 명령을 서브셸에서 실행하며, 현재 쉘 환경에 영향을 주지 않음 
(cd /tmp; ls)
pwd  # 현재 디렉토리는 원래 위치 유지

실행 결과

(file1  file2  ...)
(현재 디렉토리는 원래 위치 유지)
✔ 핵심 정리
  • 서브셸에서 실행되므로 원래 환경을 변경하지 않음
  • 일시적인 디렉토리 변경 등에 사용 가능

7. {} (현재 셸에서 실행) - 여러 명령을 묶어 실행

  • {} 안의 명령들을 현재 셸에서 실행
  • 마지막 명령어 뒤에 반드시 ;가 필요 
{ cd /tmp; ls; }

실행 결과

(file1  file2  ...)
(현재 디렉토리는 변경됨)
✔ 핵심 정리
  • 현재 셸에서 실행되므로 환경 변화가 유지됨
  • 디렉토리 변경 후 지속적으로 유지하려면 {} 사용

8. > (출력 리디렉션) - 명령 출력을 파일로 저장

  • 명령어 실행 결과를 파일에 저장 (덮어쓰기) 
ls > file_list.txt

실행 결과

  • file_list.txt 파일에 ls 출력 결과가 저장됨

9. >> (출력 리디렉션 - 추가)

  • 기존 파일 내용을 유지하면서 새로운 출력 추가 
echo "새로운 로그" >> log.txt

실행 결과

  • log.txt 파일의 기존 내용 유지 + 새로운 내용 추가됨

10. < (입력 리디렉션) - 파일 내용을 명령어 입력으로 사용

  • 파일 내용을 명령어의 입력으로 전달 
sort < names.txt

실행 결과

  • names.txt 파일을 읽어서 정렬하여 출력

11. 2> (표준 오류 리디렉션) - 오류 메시지를 파일로 저장

  • 표준 오류(에러)를 특정 파일에 저장 
ls nonexistentfile 2> error.log

실행 결과

  • 오류 메시지가 error.log에 저장됨

12. /dev/null로 출력 버리기

  • 출력 또는 오류 메시지를 버릴 때 사용 

command > /dev/null 2>&1
- 표준 출력(>)과 표준 오류(2>)를 모두 /dev/null로 보내서 출력되지 않음

정리

연산자 설명 예제
; 순차 실행 (성공/실패 상관없음) echo "A"; echo "B"
&& 앞 명령이 성공하면 실행 mkdir test && cd test
|| 앞 명령이 실패하면 실행 mkdir test || echo "실패"
| 앞 출력 → 다음 입력 ls | grep ".sh"
& 백그라운드 실행 sleep 10 &
() 서브셸에서 실행 (cd /tmp; ls)
{} 현재 셸에서 실행 { cd /tmp; ls; }
> 출력 리디렉션 (덮어쓰기) ls > file.txt
>> 출력 리디렉션 (추가) echo "test" >> log.txt
< 입력 리디렉션 sort < names.txt
2> 표준 오류 리디렉션 ls nonexistent 2> error.log

쉘에서 명령을 조합하면 강력한 자동화 및 데이터 처리 작업을 쉽게 수행할 수 있음 🚀
